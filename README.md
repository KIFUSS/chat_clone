# Telegram Clone (Full-Stack Messenger)

Профессиональный учебный Full-Stack проект по созданию масштабируемого клона мессенджера Telegram с многоэтапной клиент-серверной авторизацией, декомпозированной архитектурой и интеграцией с базой данных в режиме реального времени.

## 🚀 Основной функционал

- **Монорепозиторий:** Единая экосистема управления фронтенд и бэкенд частями приложения в одном Git-репозитории.
- **Многоэтапный Auth Flow:** Линейный процесс входа: ввод номера телефона ➔ генерация и сверка 5-значного OTP-кода по SMS ➔ динамическая проверка наличия пользователя в БД ➔ регистрация новых аккаунтов («О себе»).
- **In-Memory & Persistent Storage:** Временное хранение сессионных кодов верификации в оперативной памяти сервера и персистентное сохранение профилей пользователей в базе данных.
- **Двухпанельный UI Мессенджера:** Split-screen интерфейс со списком чатов, умным сжатием длинного текста (`truncate`) и независимым изолированным скроллом области сообщений (`overflow-y-auto`).

## 🛠 Технологический стек

### Фронтенд (client)
- **React 19 / TypeScript:** Строгая типизация компонентов, пропсов и интерфейсов данных (`interface`, литеральные типы состояний шагов, явные импорты типов `import type`).
- **Tailwind CSS v4:** Современная компонентная верстка, адаптивные сеточные UI-элементы, кастомные фоновые градиенты.
- **React Router Dom:** Маршрутизация приложения, программный редирект пользователей с защитой истории переходов (`useNavigate` с флагом `replace: true`).

### Бэкенд (server) & Инфраструктура
- **Node.js / Express:** Быстрый асинхронный HTTP API-сервер для обработки POST-запросов и маршрутизации бизнес-логики.
- **MongoDB / Mongoose:** Документоориентированная NoSQL база данных (LTS-версия 8.0). Валидация типов данных на уровне приложения через декларативные схемы Mongoose.
- **CORS / Dotenv:** Конфигурация мидлваров безопасности для межпортового взаимодействия кросс-доменных запросов и изоляция конфигурационных секретов.
- **Nodemon:** Автоматизация среды разработки и горячая перезагрузка сервера на лету.

## ⚙️ Инструкция по локальному развертыванию

### 1. Клонирование репозитория
```bash
git clone https://github.com
cd chat_clone
```

### 2. Настройка и запуск Базы Данных
Убедитесь, что у вас установлена локальная СУБД **MongoDB** (стабильная LTS-версия). Служба базы данных должна быть активна в операционной системе и слушать стандартный порт `27017`.

### 3. Запуск Бэкенда (Server)
Перейдите в папку сервера, установите зависимости и запустите dev-сервер:
```bash
cd server
npm install
```
Создайте в папке `server` файл `.env` и добавьте строку подключения:
```env
MONGO_URI=mongodb://127.0.0.1:27017/telegram_db
```
Запуск:
```bash
npm run dev
```

### 4. Запуск Фронтенда (Client)
Откройте параллельную вкладку терминала, перейдите в папку клиента и запустите Vite:
```bash
cd client
npm install
npm run dev
```

## 📐 Архитектурные паттерны проекта

В ходе разработки были применены передовые подходы к проектированию веб-приложений:
1. **Паттерн Smart/Dumb Components:** Страницы выступают диспетчерами верхнего уровня, в то время как интерфейсные шаги декомпозированы в изолированные «глупые» визуальные компоненты, принимающие данные через пропсы.
2. **Изоляция бизнес-логики (Custom Hooks):** Вся сетевая и стейт-логика вынесена из разметки страниц во внешние кастомные хуки (`useAuthFlow.ts`, `useChat.ts`), что обеспечивает высокую читаемость и простоту тестирования.
3. **Паттерн Barrels (index.ts):** Оптимизация структуры импортов с помощью сквозных индексных файлов экспорта, предотвращающая раздувание шапок компонентов.
4. **Централизованный слой типов (types.ts):** Изоляция интерфейсов данных и утилит типов (Mongoose-модели, словари `Record`), исключающая дублирование кода.
